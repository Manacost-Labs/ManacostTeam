# Постоянные источники Hearthstone и архив расшифровок

По указанию владельца от 21.10.2026 все 39 `owner_required` источников из
[реестра](domains/hearthstone-sources.json) проверяются в каждом новом
исследовании Hearthstone, включая `/funmeta`, `/meta-report`, гайды по героям
и исследовательскую часть публикации. Это дополнение к Blizzard, Manacost MCP,
статистическим площадкам, X и Reddit, а не замена прежних источников.

## Обязательный обход

1. В новом запуске создай `owner-source-coverage.json` командой `plan` ниже.
   Для каждого источника выполни тематический поиск, затем прочитай подходящие
   материалы. Поиск по каналу/сайту предпочтительнее чтения главной страницы.
2. Сохрани настоящий запрос, время попытки и статус: `inspected`,
   `no_relevant_results`, `blocked` или `excluded`. Для `inspected` нужны
   `inspected_urls`, для остальных — конкретная `reason`. Исключение требует
   основания из пользовательского ограничения; другой обычный режим канала
   сам по себе не заменяет поиск по теме. Не скрывай неудачные обращения.
3. В `findings` запиши полезный факт, условие, контрдовод или отсутствие
   подходящих материалов. Отдельно веди обычные `queries.jsonl`, `sources.jsonl`
   и Evidence. Заполненный чеклист ещё не подтверждает ни глубину, ни факты.
4. `coverage` должен отчитаться обо всех 39 строках. Проверка принимает журнал
   оператора и не доказывает, что обращения действительно выполнялись.
   Недоступность источника явно ограничивает охват; не останавливай другие ветки.

```text
python scripts/source_library.py plan RUN/owner-source-coverage.json
python scripts/source_library.py coverage RUN/owner-source-coverage.json
```

Реестр также совместим с `registry_seed.py`; для обязательных источников
используй отдельный чеклист, чтобы попытки по всем площадкам были видны даже
при узком режиме. Планы никогда не выдаются за выполненный поиск.

## Как добирать данные

| Источники | Рабочий маршрут и обязательный контекст |
|---|---|
| Hearthstone-Decks, JudgeHype | Французские запросы `deck`, `guide`, `mulligan`, `mise à jour` + локальное имя/патч. Читать текст и полный состав, следовать ссылкам на первоисточник; голоса не являются винрейтом. |
| hs.blizzard.cn | Китайский официальный первоисточник: `补丁`, `平衡`, `更新` + версия; сохранять регион, дату и отличия от глобальных заметок. |
| PTT Hearthstone, Gamer.com.tw | Традиционный китайский: `爐石`, `牌組`, `攻略`, `留牌`, `英雄戰場`. Читать пост и содержательные ответы, сохранять даты/авторов/возражения. Не сливать независимые мнения и цитирование одного автора. |
| Out of Games, HearthPwn decks/forums | Исходная статья, список и код колоды, автор, формат, обновления и обсуждение. Проверять актуальность и легальность независимо от заголовка. |
| Bilibili | Тематический поиск `炉石传说` / `酒馆战棋` + сущность/патч. Сохранять BV/av ID, часть видео, автора, описание, оригинальные субтитры и таймкоды. Для доступного локального аудио допустим faster-whisper. TranscriptAPI предназначен для YouTube. |
| note.com, BeerBrick | Японские `ハースストーン`, `デッキ`, `マリガン`, `バトルグラウンド` + проверенное локальное имя. У BeerBrick сохранять результат игрока, сервер, дату и код; у note.com искать конкретных авторов, не общий домашний поток. |
| Inven | Корейские `하스스톤`, `덱`, `공략`, `멀리건`, `전장` + сущность. Сохранять автора, дату, оригинал, код и границы заявленного результата. |
| Все 23 YouTube-канала владельца | Каждый handle хранится в реестре. Сначала тематический поиск по каналу, проверка личности/режима/даты и патча записи; затем описание, код, связанные материалы и сегменты расшифровки. Не назначать профессиональный статус по названию канала. |
| Coin Concede, Born to Be Wild, Data Reaper Podcast, Hearthstone Commute / Walk to Work | Найти выпуск по теме/дате/патчу, прочитать show notes, затем расшифровку нужных фрагментов. Born to Be Wild посвящён Вольному; оценки ведущих Data Reaper не подменяют таблицы статистики. У Libsyn главная может быть SPA: для Walk to Work используй `https://hearthstonecommute.libsyn.com/rss`. |

Не делай вывод о точном написании игрового имени по ASR или машинному переводу.
Сверяй публикационные русские имена с текущим каталогом KHS/Manacost.

## Scrape.do

По постоянному указанию владельца поиск в интернете и HSGuru начинай
через `scripts/source_access.py` по [provider reference](source-providers.md).
Для Reddit основной маршрут — RedditAPI с регулярным чтением нескольких
независимых обсуждений и комментариев; Scrape.do остаётся резервом.
Проверяй фактический домен результата: ответ 200 и непустая общая выдача
не означают, что поиск по китайскому форуму сработал. Недоступный или старый
материал не превращается в текущее подтверждение из-за удобного сниппета.

Интерактивный веб-поиск и доступные страницы остаются способом discovery.
Для повторяемого чтения публичных страниц используй `collect` по
[контракту получения источников](source-acquisition.md): сохранённые валидные
ответы, реальные паузы после отказов и явные ограничения актуальности.
Одноразовый `fetch` оставь для адресной транспортной диагностики.

```text
python scripts/source_library.py doctor
python scripts/source_access.py collect --url https://www.hearthpwn.com/decks --canary Hearthstone --output RUN/hearthpwn.json
```

Ключ `SCRAPE_DO_API_TOKEN` загружается из окружения или закрытого локального
хранилища. Коллектор использует транспорт `source_access.py`, проверяет
контракт ответа и сохраняет фактические diagnostics стоимости провайдера,
когда они доступны. Некитайские страницы не становятся CN-записями.
Успешное извлечение HTML не означает
полноту комментариев или расшифровку видео. Для китайских deck/statistics
records используй также [специализированный маршрут](chinese-hearthstone.md).
Не обходи вход/платный доступ. Не считай CAPTCHA и пустой SPA успешной страницей.

## Подкасты и видео: сначала постоянный архив

Каноническое локальное хранилище — `research/library/transcripts/` в проекте.
Оно не находится в `build/`, не имеет TTL и не очищается после исследования.
Полные чужие расшифровки и аудио исключены из Git и portable ZIP; политика и
код версионируются. В standalone-пакете установи `HEARTHSTONE_SOURCE_LIBRARY`
на постоянную папку проекта; `--library PATH` задаёт её для одного вызова.
Копия на этом компьютере не является резервной копией на другом устройстве.

Порядок работы с каждым выпуском:

1. Найди в архиве существующий выпуск/фрагменты; одна и та же запись повторно
   не расшифровывается ради новой статьи или нового патча.
2. Найди публичные RSS, show notes и издательскую расшифровку. RSS — каталог,
   а не текст выпуска. `podcast:transcript` сохраняется как ссылка для чтения.
3. Для подтверждённого YouTube-зеркала используй `youtube`: сначала локальный
   архив, затем TranscriptAPI. `public-captions` — только явно обозначенный
   запасной маршрут. Не отправляй MP3/Bilibili URL в TranscriptAPI.
4. Если подходящих субтитров нет, получи доступное публичное аудио в локальный
   файл и запусти `transcribe` через faster-whisper. Не скачивай заново уже
   сохранённое аудио. Путь к локальному аудио нужен только при первом запуске:
   cache HIT не импортирует модель и не читает аудиофайл.
5. Используй постоянные `series` и RSS `episode_id`/GUID. Номер из заголовка
   служит запасным ID только после проверки. URL аудио может измениться.
   При переходе с YouTube на аудио сначала проверь YouTube-запись того же
   выпуска; мост между GUID и video ID внеси в metadata, не создавай вторую
   расшифровку. Один и тот же video ID у короткой/полной ссылки даёт один ключ.
6. Сохрани оригинальные сегменты, язык, источник, заголовок, дату выпуска,
   модель/provider, дату получения, хеш текста и записи. Перевод и обзор
   храни отдельно: они не заменяют оригинал. У ASR нет проверенной
   атрибуции говорящих; не приписывай реплики конкретному ведущему без проверки.
   Дату записи сохраняй отдельно: во вступлении может быть более ранняя дата,
   чем RSS. Полные расшифровки чужих выпусков сохраняй при подтверждённом
   разрешении; иначе готовь конспект с таймкодами и краткими выдержками.
7. Только явный `--refresh` запускает обработку заново; прежний файл остаётся
   в `revisions/`. Повреждённый архив вызывает ошибку, а не платный повтор.
   Блокировка эпизода защищает от двух одновременных обработок; после аварии
   сначала проверь процесс, затем вручную убери оставшийся `.lock` каталог.

```text
# Локальный поиск, исходник и таймкоды; никаких сетевых вызовов
python scripts/source_library.py search "mulligan"
python scripts/source_library.py show ARCHIVE_KEY

# RSS сохраняется обычным веб-инструментом; parser принимает исходные RSS/Atom bytes
python scripts/source_library.py feed --file RUN/podcast.xml --url https://feeds.libsyn.com/70241/rss --output RUN/episodes.json

# Первый вызов сохраняет оригинальную расшифровку; повторы читают архив
python scripts/source_library.py youtube --video YOUTUBE_URL --metadata RUN/episode-metadata.json

# Резервные публичные субтитры; требуется отдельный optional package
uv run --with youtube-transcript-api python scripts/source_library.py youtube --video YOUTUBE_URL --provider public-captions

# Локальное ASR; первая установка/загрузка модели требует сети и дискового места
uv run --python 3.12 --with-requirements references/examples/source-library-requirements.txt python scripts/source_library.py transcribe --series coin-concede --episode-id RSS_GUID --source-url EPISODE_PAGE --audio LOCAL_MP3 --metadata RUN/episode-metadata.json --model small --device cpu --language en

# Импорт прочитанных издательских/других timed segments
python scripts/source_library.py import --series coin-concede --episode-id RSS_GUID --source-url EPISODE_PAGE --file RUN/timed-transcript.json
```

`episode-metadata.json` содержит реальные `title`, `published_at`, `feed_url`,
`audio_url`, `youtube_video_id` (если зеркало проверено), `patch_context` и
`completeness` (`full`/`partial`/`unknown`). Дату загрузки и дату обсуждаемых
матчей не объединяй. Для импорта используй объект `provider` и `segments` с
числовыми `start`, `end`, `text`; формат не подтверждает правдивость текста.
Не ставь `full`, если обработан только фрагмент. Модель `small` — настраиваемый
CPU default, а не обещание достаточной точности Hearthstone; для публикационных
цитат сверь звук, имена, числа, отрицания и доступный видеоконтекст.

Поиск возвращает исходные таймкоды; ссылки на конкретный момент подкаста
составляй только если плеер их поддерживает. ASR отражает речь, а не истинность
или актуальность совета. Сохраняй краткие цитаты в Evidence, не публикуй полный
чужой транскрипт в статье или ответе.

Документация поставщиков: [TranscriptAPI](https://transcriptapi.io/docs),
[faster-whisper](https://github.com/SYSTRAN/faster-whisper),
[Scrape.do](https://scrape.do/documentation/).

Локальный Windows runtime установлен в `research/library/.venv/` основного
репозитория. Запускай скрипт через его `Scripts/python.exe`, если не используешь
`uv run`. Зафиксированные optional зависимости находятся в
`references/examples/source-library-requirements.txt`: faster-whisper 1.2.1
несовместим с `av` 19 из-за удалённого `metadata_errors`; рабочая комбинация
проверяется реальным декодированием/ASR, а не одним импортом. Причина описана
в [upstream issue](https://github.com/SYSTRAN/faster-whisper/issues/1589).

Для длинных английских подкастов на текущем компьютере проверен large-v3 на
CUDA/float16, batch 8. `source_library.py transcribe --device cuda --model large-v3`
подключает DLL из установленных NVIDIA wheels на Windows. CPU default small
остаётся доступен для других машин. GPU dependencies устанавливаются отдельно:
`references/examples/source-library-cuda-requirements.txt`; не включай DLL,
модели и venv в ZIP.
CLI сохраняет также стабильный `.md` рядом с хешированной JSON-записью; cache
HIT не переписывает уже существующий читаемый экспорт.
