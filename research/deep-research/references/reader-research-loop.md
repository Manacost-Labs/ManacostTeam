# Адресный поиск для полезного и выразительного текста

Цель — объяснить решение читателя: что выбрать, почему, при каких условиях
и когда поступить иначе. Это вопросы по применимости, а не обязательный
шаблон каждого раздела. До прозы соберите основания; после — проверьте,
что абзац добавляет новую мысль, условие или понятный переход.

Используются прежние reader_questions, source followups и query planner.
Новый исполнитель не создаёт claims, не объявляет вопрос отвеченным,
не считает результаты поиска прочитанными источниками и не разрешает публикацию.

## Цикл

В native publication цикл выполняется до submit/freeze этапа sources. Передайте
в этот этап все прочитанные материалы. Если после фиксации понадобятся новые,
создайте новый publication run с расширенным sources: старые snapshots и
связанные хеши не переписываются, handoff не может ссылаться на отсутствующий источник.

1. В `plan.json` заполните reader_questions с question_id, question, priority,
   search_phrases по языкам; section_id — если определены разделы статьи.
   `target_platform` необязателен: web (по умолчанию), reddit, x или youtube.
2. Запустите `python3 scripts/reader_research.py next RUN_DIRECTORY`.
   Для Hearthstone по умолчанию EN/RU; `--language` можно повторять, включая zh.
   Нужны реальные локализованные фразы: исполнитель не переводит их автоматически.
3. Выполните первую подходящую `command` из JSON как массив аргументов.
   Это `reader_research.py search` с query-id и query-sha256. Команда самодостаточна
   и содержит абсолютные пути. Выполняйте задания одного run последовательно.
4. Изучите сохранённые результаты; откройте подходящие материалы прежним
   Collector / `fetch_source.py`, свяжите source ID с выполненным запросом.
   Для Reddit читайте содержательные комментарии; для видео — расшифровку.
5. После чтения запишите в query `observations.summary`, полезные novelty с
   evidence_ids и followup_questions с parent_question_id, why_it_matters,
   search_phrases. Для смены площадки задайте target_platform; иначе followup
   наследует площадку родительского вопроса. Вызовите next повторно.

```json
{
  "reader_questions": [{
    "question_id": "RQ-1",
    "question": "Когда следует отказаться от предложенного решения?",
    "priority": "material",
    "status": "open",
    "target_platform": "web",
    "search_phrases": {
      "en": "actual topic decision exceptions",
      "ru": "конкретная тема условия и исключения решения"
    }
  }],
  "research_budget": {"max_queries": 30}
}
```

Это пример формата, не готовые поисковые фразы для игровой статьи.
Подставляйте проверенные названия и конкретный вопрос из задания.

## Маршруты и сохранность

- Общий веб и HSGuru: Scrape.do через source_access, с проверкой site scope.
  Reddit: RedditAPI; X: GetXAPI; YouTube: TranscriptAPI через существующий
  community_sources. Отказ не вызывает автоматическую смену провайдера.
- Исполнитель использует прежние ключи/лимиты. `next` ничего не пишет и
  не обращается к сети. `search` действительно обращается к провайдеру и
  может расходовать его бюджет. В этой разработке такие вызовы проверялись
  на offline fixtures, без платных запросов и без изменения production.
- Запрос фиксируется в query-plan, результат — в search-results с SHA256,
  попытка — в queries; кандидаты получают deferred. `result_source_ids` остаётся
  пустым до реального открытия материала. Ответы и источники не выдумываются.
- Одинаковая фраза на разных площадках означает разные запросы. Одинаковые
  запросы в одной площадке объединяют ссылки на вопросы и разделы.
- Бюджеты по умолчанию: quick 10, deep 30, exhaustive 60; учитываются попытки
  и уже запланированные задачи. --max-queries — явное переопределение.
  Изменение плана/бюджета/маршрута делает старую SHA-задачу недействительной.
- CLI возвращает 0 для выполненного поиска (включая no_results), 1 после
  сохранения блокировки провайдера, 2 для неверного/устаревшего задания.
  Даже exit 0 не подтверждает чтение материала или истинность совета.
- Параллельный запуск блокируется lock. После начала остаётся attempt reservation:
  повтор того же query-id запрещён. После прерывания next показывает interrupted_search;
  не удаляйте lock/reservation ради автоматического повтора оплаченного запроса.
  Сначала выясните результат попытки и сохраните её происхождение.
- Одно site-ограничение задаётся именем хоста. Смешение площадок и URL-пути
  в site: отклоняются до обращения к провайдеру. Symlink-выходы запрещены.

Статусы needs_reader_questions, search_required, interrupted_search,
unresolved_no_search, questions_answered описывают очередь. Даже последний
возвращает factual_approval=false: semantic review и publication handoff
остаются обязательными. Обход всех 39 источников владельца, provenance,
актуальность и независимость не заменяются этим адресным циклом.

## Проза после поиска

Автор получает проверенные причины, условия и примеры через прежний handoff.
Сначала выстройте содержательный разбор; затем отдельно вычитайте прозу:
точные глаголы, естественный порядок слов, связность и ритм. Убирайте повтор
мысли и пересказ очевидного читателю. Новая причина, исключение и важная
оговорка — полезная плотность, а не вода. Образ или сравнение могут прояснить
уже подтверждённое; квоты метафор, выдуманного опыта и декоративных сцен нет.

Проверки кода не доказывают улучшение статей. Для сравнения сохраняйте
одинаковые модель/промпт и бюджет исследования; оценивайте полезную конкретику,
сохранность смысла, связность и приятность чтения на реальных материалах.

## Тип утверждения и решения игроков

Применяй [контракт claim_kind](claim-semantics.md): каждый новый claim —
mechanic, observation или opinion. Наблюдение сохраняет размер выборки и
срез без придуманной причины; мнение — имя и источник. Для обзоров стратегий
Полей сражений и колод обязательны конкретные решения сильных игроков:
сначала research/library/transcripts/, затем записи игр и стримы. Сохрани
момент (ход/золото/уровень таверны или мана), действие, названную альтернативу,
исход, URL и таймкод либо цитату расшифровки. Заполни прежние observed decision
cards, включи strategy_review в manifest/plan. Без решений handoff говорит
«блок советов писать не из чего»; общие слова не закрывают пробел.
