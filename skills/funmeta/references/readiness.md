# Готовность исследования и граница актуальной меты

Читайте до отбора, особенно после релиза/баланса или при недоступных таблицах.
`assess selection.json` — read-only диагностика; `check`, `audit` и смысловая
проверка сохраняются. Команда не выполняет поиск, не меняет pending на include,
не выдает разрешение на экспорт и не доказывает истинность записанных фактов.

## Период матчей, а не дата запроса

Новый запуск v2 содержит `readiness_policy: 1` и незаполненный `meta_context`:

```json
{
  "meta_context": {
    "effective_at": "2026-10-20T19:00:00+02:00",
    "source_id": "official-release",
    "reason": "Пример формы: подтвержденное время значимого изменения пула"
  }
}
```

Это пример структуры, не доказательство конкретного релиза. Определите границу
по полностью прочитанному официальному источнику, проверенному в `as_of`:
последнее дополнение, значимый баланс или изменение механики. Номер последнего
хотфикса и начало нового игрового пула могут иметь разные даты. В reason
объясните выбор; не назначайте новый пул каждому косметическому исправлению.

У каждой выбранной мета-таблицы сохраняйте:

```json
{
  "data_kind": "observed",
  "data_period": {
    "start": "2026-10-20T17:00:00Z",
    "end": "2026-10-20T18:00:00Z"
  }
}
```

Период должен описывать реальные матчи этой таблицы. Он непустой, с явными
часовыми поясами; UTC и эквивалентные смещения сравниваются одинаково. Начало
не раньше effective_at. Смешанная выборка до/после обновления не подтверждает
текущую мету — найдите фильтр после события или другой источник. Одного
`updated_at`, `fetched_at`, даты публикации и свежей проверки недостаточно.
Не восстанавливайте неизвестный период из времени скачивания. При неизвестной
границе или периоде сохраняйте пробел, а не придумывайте точность.

`observed` означает прочитанную статистическую таблицу матчей. Подборка
«колоды первого дня», прогнозы автора и обсуждение возможных комбинаций —
теорикрафт. Такие публикации могут быть deck/community-источниками; они не
заменяют две независимые мета-таблицы. Метаданные периода сами по себе также
не доказывают качество выборки: ранги, объем, классификацию и независимость
издателей по-прежнему проверяет исследователь.

`check` и `export` применяют временной контракт к новым запускам. Старые
журналы без readiness_policy остаются читаемыми; `assess` предупреждает, что
период не проверялся. Не удаляйте флаг из нового запуска ради обхода проверки.

## Что показывает assess

- Общие блокеры: целостность снапшотов, официальный патч, доступность и
  независимость мета-таблиц, период данных относительно официальной границы.
- Отдельно для каждого include/pending: полный источник состава, совпадение
  кода с независимо прочитанным списком, происхождение кода, запись проверки
  легальности, отличие плана и ограничения, дословные свидетельства объяснений,
  результаты сравнения с выбранными таблицами. Reject не готовится к выдаче.
- Распределение полных deck-источников по publisher и предупреждение о
  преобладании одного издателя. Называйте одного издателя одинаково у разных
  страниц/зеркал; не выдавайте имя автора и его сайт за независимых издателей.

`recorded_checks_complete` относится только к перечисленным диагностическим
проверкам. Это не заключение о фане, легальности в клиенте, содержании цитат,
полноте поиска или готовности выпуска. Даже заполненный отчет оставляет
`export_approved: false`; окончательные gates не меняются.

Если мета недоступна, продолжайте проверять составы, коды и взаимодействия.
Отсутствие таблицы не должно скрывать неправильное code_provenance или пустые
explanation_evidence. Обсуждать исследовательский черновик допустимо, называть
его полным выпуском с подтвержденным статусом «вне меты» — нет.

## Поиск, который дает разные находки

Начните с широкого каталога класса, затем сравните авторские разборы,
сообщества и адресные поиски по механике. Названия, кнопки копирования и слово
«meme» — наводки. Для каждого кандидата отдельно установите конкретную
интересную ситуацию, воспроизводимый порядок действий и отличие от метового
плана. Полная стартовая подборка крупного издателя может почти целиком
состоять из претендентов в мету; не переносите ее в выпуск по одному классу.

Несколько вариантов с одним Древним богом могут играть по-разному. Сравните,
например, источник ресурсов, подготовку хода и способ завершения партии.
Косметическая замена поддержки при прежних решениях игрока не создает новую
находку. Диагностика концентрации помогает расширить поиск, но не вводит
обязательное число авторов, колод или карт. Отбор остается редакционным.
Планировщик добавляет известный патч к веб-запросам, сохраняя каталог без
фильтра по названию. В новых запусках два разных полных списка одного
издателя не закрывают ветку поиска независимого автора: доступна ограниченная
адресная попытка по прежним правилам повторов. Это поиск, не квота принятия.

Для API сначала прочитайте реально доступные параметры и схему. Запрашивайте
нужные поля и небольшие порции, сохраняйте ответы и повторно используйте
уже проверенные DBF. Не считайте пустой ответ на неподтвержденный оператор
фильтра отсутствием карты. При 429 соблюдайте Retry-After/уменьшайте частоту;
не посылайте немедленно новую большую пачку. Пока источник ограничен,
проверяйте уже полученный материал или другую площадку.

Пропущенное число в динамическом тексте карты, конфликт RU/EN и подпись без
условий требуют сверки с полным определением/официальным изображением.
Не дополняйте их по памяти. Для комбинации сохраняйте расходы маны, порядок,
условие «пока карта в руке», пул погибших, дополнительные зоны, место на поле
и случайность целей. Код и два декодера этого не устанавливают.
