# Импорт каталога и очередь составов

Используй, когда `search_decks` уже вернул реальный ответ. Команда не выполняет
сетевой запрос и не заменяет исследование первоисточника.

## Как сохранить ответ

Вызови доступный `mcp__manacost__search_decks` с точными параметрами из `next`.
Сохрани JSON с двумя полями:

```json
{
  "request": {"className": "Mage", "format": "standard", "limit": 30, "offset": 0},
  "response": {"content": [{"type": "text", "text": "ТОЧНЫЙ JSON ИЗ РЕАЛЬНОГО ОТВЕТА MCP"}]}
}
```

Это форма, не готовый источник: подставь фактический ответ, не плейсхолдер.
`response` может содержать исходный MCP result либо его разобранный JSON
с `data.data`, `data.meta` и `retrievedAt`. Сохрани исходные поля, код и даты.
Укажи реальный request, а не предполагаемый. Фильтры автора/названия сюда
не входят: они не доказывают охват общей страницы класса.

```text
python <skill>/scripts/funmeta.py catalog <run>/selection.json <capture.json>
python <skill>/scripts/funmeta.py plan <run>/selection.json --limit 11
```

Импортёр проверяет класс/формат/страницу и число возвращённых строк по count.
Он сохраняет точные байты capture в `sources/`, SHA-256, записи источников,
исходные даты и коды, реальную попытку поиска и next_offset. Страницы идут
последовательно; последняя страница закрывает продолжение. Неполный ответ
отклоняется, чтобы случайно не пропустить непрочитанные строки.

Повтор того же файла ничего не меняет. Отличающийся ответ уже сохранённой
страницы не подменяет доказательства: для нового патча/обновления начни новый
запуск. Изменённый снапшот отклоняется при повторном импорте и check. При ошибке
проверки записи журнал сохраняется; material/review не переписываются. Новый
успешный импорт меняет хеш журнала, поэтому прежний отзыв становится неактуальным.

## Что разбирать первым

`leads_to_inspect` в новом `next` или в `plan` для любого v2 — очередь для
чтения оригинальных страниц:

- Одинаковые карты, количества, формат и дополнительные зоны объединяются;
  разные портреты героя не создают новую колоду. Все source_ids сохраняются.
- Классы чередуются. Нельзя разбирать десяток соседних сборок одного класса,
  пока другой класс не получил первой попытки. Уже взятые в candidates
  источники/независимые составы передаются в candidate_tasks и не повторяются.
- stale, отсутствие даты исходной публикации, данные не за дату запуска,
  отсутствующий/нечитаемый код показываются как предупреждения. added_at —
  дата появления в каталоге, updated_at — обновление записи; это не дата автора.
- Будущая дата публикации/появления отправляет запись в deferred_catalog_leads:
  перепроверь дату и доступность карт перед рассмотрением в текущем запуске.

Внутри класса предпочтение у записей с меньшим числом проблем данных; это
удобство очереди, не рейтинг фана, силы или достоверности игрового плана.
Отсутствие предупреждений тоже не подтверждает актуальную легальность.
Если код сломан, открой исходный список и найди экспорт/восстанови его по
контракту discovery. Не теряй интересную идею только из-за сбоя экспорта.

## Когда зацепка становится кандидатом

Источник импорта имеет `access: excerpt`. Даже корректный код — только экспорт,
а не независимо прочитанный список. Импорт **не** создаёт include, verified,
deck_list, мета-проверки или положительный отзыв и не закрывает класс.

Открой ссылку, прочитай весь состав и объяснение, затем создай pending/reject
кандидата с причиной и source_ids. Полное чтение оригинала сохрани отдельным
снапшотом/источником с настоящими выдержками; добавь его к кандидату.
Проверь необычный план, отличие от меты, текущую легальность, код и все зоны.
Нельзя заполнить независимый deck_list только декодированием импортированного
кода: такая сверка проверяет код самим собой. После отбора действуют прежние
check, смысловая проверка и обязательные коды в художественном тексте.
