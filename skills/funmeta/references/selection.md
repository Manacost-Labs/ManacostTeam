# Журнал отбора Funmeta

`selection.json` хранится в каталоге запуска вместе с `material.md` и `sources/`.
В репозитории запускай в ignored `build/funmeta/<дата>-<формат>/`.
`init` создаёт намеренно незаполненный журнал: он не проходит `check`, пока
исследователь не подтвердит патч и не соберёт источники.

## Источники

`schema_version: 1`, `as_of: YYYY-MM-DD`, `format: standard|wild`, `patch` —
подтверждённый актуальный номер; `patch_source_id` ссылается на официальный
источник, прочитанный в дату `as_of`. `sources` — массив записей:

```json
{
  "id": "meta-a",
  "kind": "meta",
  "title": "Название реально прочитанной таблицы",
  "url": "https://example.org/table",
  "checked_on": "2026-10-19",
  "patch": "ACTUAL_PATCH",
  "format": "standard",
  "access": "full",
  "scope": "Период данных, ранги, регион, ограничения классификации",
  "snapshot": "sources/meta-a.txt",
  "sha256": "SHA256_BYTES"
}
```

Это пример формы, не источник и не данные игры. `kind` принимает official,
meta, deck, card, community. Для каждого источника сохрани реально прочитанное
содержание в snapshot и SHA-256 его байтов. Ссылки на чужие локальные файлы или
выход за каталог запуска запрещены. В снапшотах сохраняй происхождение,
дату публикации и контекст цитат, а не только собственный пересказ.
Для видео укажи доступный транскрипт/таймкоды и ограничения доступа.

`meta_source_ids` перечисляет хотя бы две таблицы разных издателей одного
формата и текущего патча. Для каждой обязательны `access: full`, `scope` и
проверка не старше 14 дней относительно `as_of`. Возраст проверки — только
верхняя техническая граница: устаревшее содержимое не становится свежим.
Проверяй актуальность периода вручную. Скрипт различает hostname, но не умеет
распознавать зеркала и общего владельца; независимость подтверждает агент.
Если подходящих таблиц нет, сохрани черновик и объясни отсутствие проверки.

## Кандидаты

Каждая запись `candidates` имеет уникальный `id`, `class`, `name`,
`decision: include|reject|pending`, `reason` с основанием решения.
Отклонённые/непроверенные кандидаты остаются в журнале, но не в итоговой подборке.

Для `include` дополнительно нужны:

- `premise`: необычная задумка и отличие от метовых планов;
- `game_plan`: как играют и побеждают, с условиями комбинации;
- `fun_moment`: конкретное интересное взаимодействие/игровой опыт;
- `limitations`: где план не срабатывает;
- `source_ids`: IDs прочитанных источников, включая хотя бы один `kind: deck`
  с полным списком; `mechanics_source_ids`: подтверждения объясняемых механик;
- `legality: verified`, `legality_reason`: формат, состав, актуальный баланс,
  дополнительные зоны и ограничения карт проверены, с источниками;
- `deck_code_status: verified|unavailable`, `deck_code_reason`: как сверили код
  после декодирования или почему выдаётся только ссылка на полный состав;
  `deck_code` заполняется только для verified. Сам check не декодирует код;
- `meta_checks`: по записи `{source_id, result, reason}` для каждой выбранной
  таблицы ровно один раз. Для include допускается только `result: absent`.
  В reason сравни архетип/ядро/план, а не только имена; present/unknown исключают
  включение. Хеш снапшота не подтверждает правильность этой интерпретации.

Классы в журнале: death-knight, demon-hunter, druid, hunter, mage, paladin,
priest, rogue, shaman, warlock, warrior. Для каждого должен быть include либо
запись `gaps: {class: "конкретная причина"}`. После успешного отбора удали
начальный gap этого класса. Pending/reject не закрывает класс. Если в игре
появился новый класс, обнови контракт, не пропускай его молча.

`fun_cards` — массив `{id, name, why_fun, source_ids}`; причины и механики
подтверждаются источниками. Включённые колоды требуют хотя бы одной такой карты.
Обзор меты и читательский текст пишутся в `material.md`, а не генерируются
скриптом. Цифры и советы в нём проходят отдельную смысловую сверку.

`check` возвращает `structure_valid` с `mechanical_checks_only: true`, числом
выбранных колод и `coverage: complete|partial`. Это не статус публикационной
готовности. Даже корректный журнал с gaps остаётся частичным; полностью
заполненный журнал не доказывает истинность выводов или качество материала.
