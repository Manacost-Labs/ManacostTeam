# Журнал отбора Funmeta

`selection.json` хранится в каталоге запуска вместе с `material.md` и `sources/`.
В репозитории запускай в ignored `build/funmeta/<дата>-<формат>/`.
`init` создаёт намеренно незаполненный журнал: он не проходит `check`, пока
исследователь не подтвердит патч и не соберёт источники.

Необязательные для прежних v2 поля `catalog_captures` и `catalog_leads`
заполняет команда `catalog` по [контракту импорта](catalog.md). Сырые ответы
сохраняются с SHA-256, включая пустые страницы. Импортированная запись — excerpt,
не полный прочитанный список; очередь не заполняет `candidates`, `deck_list`,
положительные проверки или отзыв. Эти поля агент подтверждает отдельно.

## Источники

Новые запуски: `schema_version: 2`, `discovery_policy: 1`, `material_policy: 1`,
`as_of: YYYY-MM-DD`, `format: standard|wild`, `patch` —
подтверждённый актуальный номер; `patch_source_id` ссылается на официальный
источник, прочитанный в дату `as_of`. `sources` — массив записей:

```json
{
  "id": "meta-a",
  "kind": "meta",
  "publisher": "Установленный издатель таблицы",
  "title": "Название реально прочитанной таблицы",
  "url": "https://example.org/table",
  "checked_on": "2026-10-19",
  "patch": "ACTUAL_PATCH",
  "format": "standard",
  "access": "full",
  "scope": "Период данных, ранги, регион, ограничения классификации",
  "snapshot": "sources/meta-a.txt",
  "sha256": "SHA256_BYTES"
}
```

Это пример формы, не источник и не данные игры. `kind` принимает official,
meta, deck, card, community. Для каждого источника сохрани реально прочитанное
содержание в snapshot и SHA-256 его байтов. Ссылки на чужие локальные файлы или
выход за каталог запуска запрещены. В снапшотах сохраняй происхождение,
дату публикации и контекст цитат, а не только собственный пересказ.
Для видео укажи доступный транскрипт/таймкоды и ограничения доступа.

`meta_source_ids` перечисляет хотя бы две таблицы разных издателей одного
формата и текущего патча. Для каждой обязательны `access: full`, `scope` и
проверка не старше 14 дней относительно `as_of`. Возраст проверки — только
верхняя техническая граница: устаревшее содержимое не становится свежим.
Проверяй актуальность периода вручную. У зеркал указывай один `publisher`;
check требует разные hostname и хотя бы двух издателей, но не устанавливает
владельца сайтов сам. Независимость источников подтверждает агент.
Если подходящих таблиц нет, сохрани черновик и объясни отсутствие проверки.

## Кандидаты

Каждая запись `candidates` имеет уникальный `id`, `class`, `name`,
`decision: include|reject|pending`, `reason` с основанием решения.
Отклонённые/непроверенные кандидаты остаются в журнале, но не в итоговой подборке.

Для `include` дополнительно нужны:

- `premise`: необычная задумка и отличие от метовых планов;
- `material_heading` — необязательное название для заголовка четвёртого уровня
  в тексте; по умолчанию используется `name`. Внутри класса заголовки разных
  составов должны различаться. `outline` показывает их, `audit` связывает
  заголовок с нужными кандидатом, кодом и источником;
- в новых запусках `code_provenance: {kind: author-export|reconstructed-list,
  source_ids: [...]}`: хотя бы один полный deck-источник этого кандидата.
  Восстановление допустимо только из независимо прочитанного опубликованного
  состава; происхождение раскрывается под кодом. Подробности в [контракте поиска](discovery.md);
- `closest_meta_plan` и `plan_difference`: ближайший известный план и отличие
  по механизму игры/победы, а не только по названиям или числу замен;
- `game_plan`: как играют и побеждают, с условиями комбинации;
- `fun_moment`: конкретное интересное взаимодействие/игровой опыт;
- `limitations`: где план не срабатывает;
- `source_ids`: IDs прочитанных источников, включая хотя бы один `kind: deck`
  с полным списком; `mechanics_source_ids`: подтверждения объясняемых механик;
- `legality: verified`, `legality_reason`: формат, состав, актуальный баланс,
  дополнительные зоны и ограничения карт проверены, с источниками;
- `deck_code_status: verified`, `deck_code_reason`: как сверили код
  после декодирования с независимо прочитанным полным составом;
  `deck_code` заполняется только для verified. Check декодирует его и сравнивает
  с полным `deck_list`, независимо прочитанным из источника;
- `meta_checks`: по записи `{source_id, result, reason}` для каждой выбранной
  таблицы ровно один раз. Для include допускается только `result: absent`.
  В reason сравни архетип/ядро/план, а не только имена; present/unknown исключают
  включение. Хеш снапшота не подтверждает правильность этой интерпретации.

Для новых готовых подборок у каждого include нужен проверенный код.
Если получить и сверить код не удалось, оставь кандидата pending с причиной.
Состояние unavailable в прежних журналах по-прежнему читается `check`,
но `export` не допускает включённую колоду без verified-кода.

`deck_list` описывает состав; он может быть сохранён и у кандидата без кода:

```json
{"format": 2, "heroes": [7], "cards": [[1, 1], [2, 2]], "sideboards": []}
```

Это синтетический пример формата, не игровая колода. `format` равен 1 для
Вольного, 2 для Стандарта. Heroes — один начальный герой по DBF ID; cards —
пары `[DBF ID, количество]`; sideboards — тройки `[DBF ID, количество, DBF ID владельца]`.
Идентификаторы берутся из подтверждённого каталога. Порядок строк несущественен.
Повтор состава под другим названием в том же классе отклоняется, смена скина
героя не создаёт другую колоду. Игровая легальность, класс героя, размер колоды,
руны и особые ограничения подтверждаются агентом отдельно; decoder это не доказывает.

Команда `decode CODE` поддерживает обычные deckstrings v1, старые строки без
sideboard-маркера и известный sideboard-блок. Повреждённый base64, обрезанные
данные, дубликаты и неизвестные хвостовые расширения отклоняются; нельзя молча
терять неизвестные зоны. Спецификация: [HearthSim](https://hearthsim.info/docs/deckstrings/),
[sideboards](https://github.com/HearthSim/python-hearthstone/blob/master/hearthstone/deckstrings.py).

## Выдержки и реальный поиск

`evidence` — массив `{id, source_id, quote}`. Quote — дословный фрагмент
UTF-8-снапшота указанного источника, с условиями и достаточным контекстом.
Check проверяет точное присутствие фрагмента, не его смысловую поддержку.
Не вырезай условия ради более удобного утверждения и не используй собственный
пересказ как цитату. Юридически/редакционно необходимые ограничения источника
сохраняются; длинные цитаты не нужно переносить в читательскую подборку.

У включённого кандидата `explanation_evidence` связывает поля `game_plan`,
`fun_moment`, `limitations`, `legality` со списками evidence IDs. Эти выдержки
должны относиться к source_ids/механическим источникам именно этой колоды.
У `fun_cards` добавь `evidence_ids`, связанные с её source_ids.

`search_log` — массив реально выполненных запросов:

```json
{
  "id": "mage-en-1", "class": "mage", "language": "en",
  "query": "реальный поисковый запрос",
  "status": "inspected", "source_ids": ["deck-source"],
  "notes": "Что прочитано, что удалось или не удалось подтвердить"
}
```

Статусы: `inspected` — источник действительно прочитан, IDs обязательны;
`empty`/`blocked` — нет изученных источников, source_ids должен быть пустым.
Для каждого класса нужны действительные RU и EN попытки; неудачи допустимы
как записи пробелов, но не считаются изученными материалами. У включённой
колоды должна быть связь с изученным источником поиска её класса.
Для новых запусков добавляй `channel: catalog|creators|community|build-around`,
а для адресного запроса — `focus`. Пагинация каталога сохраняется как
`next_offset` только по реально полученному общему count. Новые `next` и
`plan` предлагают каналы и задачи сверки кандидатов по [контракту](discovery.md).
`check` требует охват авторов, сообществ и адресного поиска перед gap.

У старого v2 без discovery_policy `next` сохраняет прежнее поведение:
предлагает незакрытые направления, сначала ещё не исследованные,
затем один адресный повтор для unresolved/empty/blocked.
Для адресного повтора query=null: агент формулирует новый запрос на указанном
языке по focus и найденным данным, а не повторяет общий запрос.
После двух попыток
ветка переходит в exhausted_lanes, а gap остаётся видимым. Исчерпанный поиск
не подтверждает колоду. Подсказки не записываются в журнал автоматически.

Классы в журнале: death-knight, demon-hunter, druid, hunter, mage, paladin,
priest, rogue, shaman, warlock, warrior. Для каждого должен быть include либо
запись `gaps: {class: "конкретная причина"}`. После успешного отбора удали
начальный gap этого класса. Pending/reject не закрывает класс. Если в игре
появился новый класс, обнови контракт, не пропускай его молча.

`fun_cards` — массив `{id, name, why_fun, source_ids}`; причины и механики
подтверждаются источниками и evidence_ids. Включённые колоды требуют хотя бы одной такой карты.
Обзор меты и читательский текст пишутся в `material.md`, а не генерируются
скриптом. Цифры и советы в нём проходят отдельную смысловую сверку.

`check` возвращает `structure_valid` с `mechanical_checks_only: true`, числом
выбранных колод и `coverage: complete|partial`. Это не статус публикационной
готовности. Даже корректный журнал с gaps остаётся частичным; полностью
заполненный журнал не доказывает истинность выводов или качество материала.

## Проверка материала и экспорт

После проверки источников, всех утверждений текста и ясности объяснений
создай `review.json` рядом с selection.json. Поля:

- `selection_sha256`, `material_sha256` — хеши текущих файлов из `review-digests`;
- `checked_on` — дата as_of, `verdict: pass|revise`;
- `facts_checked`, `plan_explained`, `coverage_checked` — true только после
  соответствующего чтения; `gaps_disclosed: true` обязателен при частичном охвате;
- `findings` — список замечаний; `notes` — содержательный итог смысловой проверки.

Нельзя создавать pass только потому, что прошёл check. Если утверждение не
поддержано, сузь/исправь текст или исключи кандидата. После изменений повтори
проверку. Отзыв не является человеческой или независимой оценкой без реального
участия такого проверяющего. `review-digests` не заполняет verdict и флаги.

`export selection.json --output final.md` требует прошедший check v2, хотя бы
одну выбранную колоду, актуальные хеши, pass, выполненные смысловые проверки и
пустой findings. Результат остаётся partial, если есть gaps. Скрипт не проверяет
честность заполненного отзыва; за смысловую сверку отвечает выполняющий агент.
Выходной файл создаётся только новым; черновики и прежние результаты не заменяются.

Для каждой включённой колоды `export` также требует verified-код и ту же строку
в отдельном копируемом блоке Markdown (без языка, `text` или `plaintext`).
Прежний экспорт распознаёт ограждения из трёх обратных кавычек. Сам по себе URL
или код внутри обычного абзаца не удовлетворяет этому требованию.
При `material_policy: 1` дополнительно обязателен
[audit материала](material-checks.md), который сверяет расположение кода,
разделы и классы. Описание и заголовок всё равно нужно прочитать по смыслу.
Подачу в голосе Манакоста, естественность и
разнообразие рассказа оценивай по [манере подачи](writing-style.md); скрипт
не присваивает тексту вымышленную оценку художественности.

Старые журналы v1 продолжают читаться через check с явным предупреждением;
некорректный код с меткой verified отклоняется и в них. Export v1 недоступен:
для нового исследования используй init v2, не придумывай недостающие evidence
и записи поиска и не меняй schema_version механически ради прохождения.

У прежних v2 без material_policy сохраняется прежний контракт export.
`outline`/`audit` доступны и для них, без изменения файлов. Для явного перехода
на новый контракт приведи материал к структуре, добавь material_policy: 1 и
заново проведи проверку с новым отзывом; один флаг не исправляет старый текст.
