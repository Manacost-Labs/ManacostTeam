# Поиск, который доходит до составов

`init` создаёт v2 с `discovery_policy: 1`. `next` выдаёт ближайшие задачи.
`plan selection.json --limit 11` показывает новый маршрут и для старого v2;
команда ничего не переписывает и не выполняет запросы сама. После каждого
пакета реального поиска сохраняй результаты и снова вызывай планировщик.
Для ответов каталога используй [импорт `catalog`](catalog.md): он переносит
ссылки, коды, даты и пагинацию без ручного переписывания. `leads_to_inspect`
предлагает разные составы по классам, а `candidate_tasks` — проверки уже
выбранных для разбора кандидатов. Это отдельные очереди: зацепка не становится
подтверждённой колодой автоматически.

## Сначала ширина, затем проверка

1. **Каталог.** Выполни предложенные `search_decks` для всех 11 классов без
   фильтра по автору или названию. Особенно важны `className: DeathKnight`
   и `DemonHunter`: варианты с пробелами/дефисами могут вернуть пустой результат.
   Остальные: Druid, Hunter, Mage, Paladin, Priest, Rogue, Shaman, Warlock, Warrior.
   Читай все страницы до конца каталога либо до двух разных перспективных
   кандидатов; `meta.count` — общее число записей. Для прочитанной страницы
   импортёр сохраняет `next_offset = offset + limit`, только если оно меньше count.
   Пустая/заблокированная первая страница направляет к другим источникам.
2. **Авторы.** Читай авторские списки на Hearthpwn, Hearthstone-decks.net,
   Manacost/Koloda, описания видео и доступные транскрипты. Ищи по классу и
   необычному условию победы; точный запрос по одному автору не заменяет обзор.
   При пустом результате меняй автора/площадку. Не ограничивай все запросы
   текущим месяцем: более ранний список можно проверить на текущем балансе.
3. **Сообщества.** Отдельно пройди RU и EN: профильные посты, Reddit,
   экспериментальные списки, обсуждения комбинаций. Дойди до оригинального
   полного состава. Заголовок/сниппет — только зацепка, не найденная колода.
4. **Ключевая карта.** Возьми реально прочитанную актуальную карту или механику
   и ищи связки по классу. Сохрани её в `focus` поиска / `search_focus` кандидата.
   Не придумывай названия карт. Если сборка относится к будущему дополнению,
   отклони её до даты доступности; теория до релиза не заполняет текущий класс.

Не принимай первую попавшуюся колоду ради покрытия. Цель — два разных
перспективных списка на незакрытый класс, когда источники это позволяют,
затем выбрать более интересный и подтверждённый. Цель `shortlist_target=2`
помогает первичному отбору, а не ограничивает число
колод в готовом выпуске. Include закрывает минимум класса; дополнительные
интересные направления можно брать из очереди каталога и прочитанных авторских
публикаций, если для каждого есть отдельное объяснение и полный набор проверок.
Показатель `distinct_full_source_leads` считает только pending/include с полным
источником; один состав под разными
именами не два кандидата. Отклоняй метовые планы и неработающие идеи с причиной,
после чего снова вызывай `next`. Не проверяй все варианты одного архетипа,
пока у другого класса нет ни одной зацепки.

## Как продолжать и когда признать пробел

`search_log` сохраняет реальный запрос, язык, класс, результат и
`channel: catalog|creators|community|build-around`. `inspected` требует
прочитанные source_ids; `empty`/`blocked` не содержат фиктивных источников.
Для build-around укажи `focus` — карту/механику фактического запроса.
Повторная попытка означает другой адресный запрос, не повтор первого.
Две попытки ограничивают конкретный канал и язык, а не весь поиск класса;
реальная пагинация каталога продолжается по записанному next_offset.
Старые записи без channel не исчерпывают новые каналы.

`coverage.gap_search_complete` требует реальные RU+EN попытки, каналы авторов,
сообществ и адресный поиск с focus. Новый `check` отклоняет gap без этого охвата.
Это проверка широты записей, не доказательство отсутствия колод в интернете.
Если найти и подтвердить всё равно не удалось, честный gap допустим.

`candidate_tasks` перечисляет недостающий полный список, код, легальность,
механику/отличие плана и мета-сверку. Выполняй доступную работу, даже если
`check` пока останавливается на двух мета-таблицах. Поиск и финальная приёмка
разделены: новые находки не означают, что они уже прошли критерий «вне меты».

## Свежесть и доступ к данным

Каталог содержит и метовые, и старые списки. Сохраняй fetched_at, stale,
первоначальную дату публикации, added_at и updated_at, если они доступны.
Обновление записи не доказывает свежесть колоды. `stale: true` — повод сверить
исходную публикацию/найти новый источник, а не принять запись как актуальную.
Проверяй полный состав и работу идеи после последнего баланса.

`get_content` читай до `nextOffset=null`. Если `search_cards` недоступен,
обнаружь контракт `read_records`: точное равенство по `name_en`/`dbf` в
`catalog.constructed_cards`; формат — в `catalog.constructed_format_cards`.
Не придумывай операторы filters: неизвестный `in`/массив может дать ложный ноль.
Нулевой ответ с неподтверждённым фильтром не доказывает отсутствие карты.

## Восстановление кода

Сначала ищи авторский экспорт. Если он закрыт, но весь опубликованный список
прочитан, создай отдельный JSON: `format` 1/2, `heroes: [DBF]`,
`cards: [[DBF, количество]]`, `sideboards: [[DBF, количество, DBF владельца]]`.
Проверь точные ID, героя, руны, размер списка, особые карты и дополнительные
зоны. Предписанные составом спутники не становятся сайдбордом по догадке.

`encode deck-list.json` возвращает детерминированный код с
`origin: reconstructed-list` и `legality_verified: false`. Сравни декодирование
с независимо прочитанным списком; ни encode, ни decode не устанавливают
игровую легальность. Не добавляй карты, не меняй количества ради валидного кода.

Для include нового журнала обязателен
`code_provenance: {kind: author-export|reconstructed-list, source_ids: [...]}`.
Ссылки должны принадлежать полным deck-источникам именно этого кандидата.
Восстановленный код подпиши: «Код восстановлен из опубликованного состава».
Это не авторский экспорт и не доказательство импорта в клиент; последнее
можно заявлять только после реальной проверки в игре.
