# Проверки материала

## Карты и механики

- Текст, уровень таверны, тип и `in_pool` — только из текущего каталога
  Колоды: Manacost MCP `search_cards` с `mode=battlegrounds` (`source=hero` для
  героев, `source=trinket` для Аксессуаров). Сохрани выгрузку в
  `RUN/images/cards.json`.
- Каждое предложение о механике сверяй с текстом карты. Типичные ошибки #12:
  «удваивает эффект» вместо «дает оба эффекта карты выбора»; спутать, кто кого
  поглощает; совет «охотиться» за существом 7-го уровня, которое приходит
  только из раскопок.
- Убраны из карты пула (`in_pool=false`) — пиши как об ушедших.
- Название, которого нет в каталоге ни на RU, ни на EN, остается спорным:
  перепроверь перевод, не придумывай карту.

## Картинки

- Источник — `images.card` (полная карта, текущий текст, прозрачный фон);
  `images.framed` — только овальный портрет, не подходит.
- `strips` собирает ленту: высота карты 520, зазор 60, поле 40, прозрачный
  фон. Углы ленты должны иметь альфу 0 (скрипт печатает проверку).
- Одна лента на сборку, 3–6 карт, в порядке «кор-карта → поддержка».
- Лента ключевых карт не является готовым столом. Для схемы стола проверь
  достижимость состава, число редких копий, стадию, места для покупок и
  значимые позиции. Не выводи правило из порядка на чужом скриншоте.
  Схема, подпись и статья должны описывать один случай.

## Шорткоды

`card-shortcodes` с `--format battlegrounds` только после финального текста.
Позиции считаются по байтам исходного файла (CRLF не нормализуй).

## Проверка перед выдачей

`bg_meta_report.py check ARTICLE.md --brief RUN/brief.json` ищет: отсутствие
обязательных разделов и рас, сборки без картинки, лишние таблицы, проценты и
исследовательский канцелярит, чек-листовые подзаголовки, числа в тир-листе
героев, вступление без «Приятного чтения!». Предупреждения разбирай вручную.

`ok` относится только к этой диагностике. Результат содержит
`scope=structure_and_style_signals`, `publication_ready=false` и список
необходимых независимых отзывов. Полезность совета и достоверность причин
скрипт не устанавливает; положительный отзыв модели не равен принятию владельца.

Литературный проверяющий перечитывает весь материал по разделу 0 общего
стандарта: что абзац добавляет сверх карты, не подменена ли глубина краткостью,
есть ли очевидные советы, техническая проза и повторы. Сверяет накопленные
замечания из переданного `author-context.json`, включая заголовки и подписи.
Для каждого требования и выбранного образца указывает конкретную цитату
новой статьи и объяснение соответствия или нарушения; отсутствие подходящего
образца отмечает явно. Сам check эти файлы не читает и отзывы не заменяет.
Фактологический проверяет причины советов, доступность состава, порядок
действий и согласованность схем с текстом. Замечания требуют цитаты и
конкретной проблемы, а не общего «сделать живее».
