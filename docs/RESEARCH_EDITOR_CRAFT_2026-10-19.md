# Архивные приёмы, абзацы и сдержанная редактура

Код: `993766f`, release **1.11.0**, EditorTeam 1.11.0, ResearchTeam 1.6.0,
Manacost Publish 1.5.0. Исходная редакторская база — `71745d5` / prompt v9;
первый новый вариант — prompt v10. Отдельная завершённая работа funmeta
`04dfccd` сохранена. По результатам этого полного опыта подготовлен v11:
critic не получает анализ автора даже при использовании той же модели.

## Что изменилось

В старом trace critic принимал точный текст, но мягкие предупреждения о
частоте слов запускали ещё один repair. Это давало новые перефразирования,
не связанные с конкретной трудностью читателя. Теперь внешняя мягкая
диагностика видна в анализе, задании автору, critic и QA, но требует адресного
подтверждения critic для repair. Error/blocker и все защищающие сущности
guard findings сохраняют прежний обязательный ремонт, включая warning о
добавленной сущности. Лимит ремонта и фактические/публикационные gates прежние.

Analysis раньше разбирался одной типизированной операцией: объект вместо
строки в paragraphs или weak_spots стирал весь анализ вместе с корректными
strengths. Теперь поля разбираются независимо, известные формы function и
where/issue сохраняются; остальные неверные типы отражаются в parse_warnings.
Каждая сильная цитата по-прежнему должна дословно существовать в исходнике.
Даже сбой модели анализа не скрывает диагностику от следующего этапа.

Приёмы восьми архивных гайдов встроены в реальные prompts анализа, автора,
critic и локального repair. В native `publish next` отдельный craft_guidance
передаётся sources/research/draft/literary_review. Это условные способы
объяснения, а не новые факты или неизменное оглавление:

- вопрос читателя и препятствие пониманию определяют порядок глав;
- нужный механизм объясняется до выбора, если без него выбор непонятен;
- условия, причины, границы и альтернативы ищутся и подтверждаются отдельно;
- переход продолжает мысль; вопрос, обращение и образ необязательны;
- полезный повтор сохраняет предмет или помогает справочному чтению;
- абзац делится по функции, сначала без переписывания слов; совет и условие
  остаются вместе, локальная правка сохраняет соседние улучшения и сноски.

Прежняя платность восьми архивных материалов не подтверждена; полный архив
и цитаты остаются в ignored build и не добавлены в переносимый корпус.
Reconstruct намеренно не получает мягкие замечания о стиле старого draft:
новый текст создаётся по handoff и проходит свой postflight/critic.

## Протокол свежего сравнения

Папка: `build/live-manacost-craft-2026-10-19`. Те же десять source spans,
request JSON и SHA-256, что в precision-final; manifest
`bfbd278e2d791e29f4f86a7288704fdc42891bb6532aca02f545129ea7572ce8`.
Обе версии заново вызывают Claude Sonnet 5.5 через подписочный CLI, effort
medium, одинаковые лимиты этапов. Пары идут одновременно с чередованием
порядка запуска. Retrieval off; seed/temperature CLI не фиксируются.
Все семь анализаторов должны быть доступны, AllowUnavailable=false.
Один прогон без выбора удачного ответа. Предыдущие опыты не перезаписываются.

Это ранее виденные фрагменты, не независимая контрольная выборка. Сохранение
исходного утверждения не доказывает его истинность. В rewards оставлена
исходная формулировка о двух легендарках нового дополнения: её отдельная
фактическая оговорка уже зафиксирована в предыдущем отчёте. Обычная редактура
не подменяет это исследованием и не исправляет игровой факт по памяти.

## Корректирующий проход v11

В анализе автора streams прямо предлагалось заменить «принимают участие»
на «играют». Critic получал этот analysis, когда использовался тот же model ID;
при отдельном Reviewer он уже очищался. В v11 граница независимости едина:
Analysis очищается всегда, но source, candidate, diff, tool findings,
проверенный handoff и точные keep_spans остаются. RED/GREEN воспроизводит
утечку авторского rationale и проверяет сохранность данных для рецензента.
Полные Go test/vet/build после исправления прошли.

JSON-пример critic теперь явно содержит reader_problem/benefit/meaning_risk,
которые раньше запрашивались только словами. Writer/critic проверяют
соседние слова после сокращения; ярлык «канцелярит» и короткий глагол сами
по себе не доказывают пользу замены. Фактические gates и API совместимы.
Это устранение влияния авторской подсказки, не доказанная причина каждого
ошибочного решения и не обещание безошибочного модельного редактирования.

Go-код не входит в переносимые skill ZIP; пакет 1.11.0 остаётся побайтово
тем же. Для v11 выполняется новый полный парный опыт с v9, на тех же 10
requests. Это отдельная ревизия с новым regression test; результаты v10
сохранены, удачные ответы между опытами не выбираются.
