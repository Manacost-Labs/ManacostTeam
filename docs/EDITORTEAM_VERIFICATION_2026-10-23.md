# EditorTeam: исправления и повторная проверка, 23 октября 2026

База изменения: `e89e565`. Выпуск переносимых навыков: `1.18.0`,
EditorTeam `1.13.0`, Manacost Publish `1.11.0`, ResearchTeam `1.10.4`.
Архивы прежних выпусков сохранены. Рабочая копия и переносимые пакеты обновлены;
это не подтверждение обновления уже запущенного удалённого сервера.

## Исправленные проблемы

| Проблема | Реализованная проверка |
|---|---|
| Legacy ограничивался семью практиками или пропускал неизменённый текст | Все 26 практик, пять проверок логики и семь проверок сохранения обязательны в каждом Go review, включая `facts_only` и unchanged |
| Сохранение исходника выдавалось за проверку его истинности | `original_factual_checks` отдельно оценивает исходные противоречия; область сверки с источниками назначает сервер |
| Одной неизменённой цитатой подтверждалось сохранение всего голоса | Для изменённого текста требуются пары цитат изменённых мест с объяснением пользы и риска |
| Отрицательные оценки сосуществовали с accept | Несогласованный отзыв отклоняется; нерешённые проблемы логики, смысла, источников или исходных фактов блокируют допуск |
| Результат игр и процент не сопоставлялись | Узкая контекстная арифметическая проверка; правильное исходное число автоматически не выбирается |
| Частота слова в корпусе превращалась в запрет | Корпусные предпочтения стали рекомендациями; явные нормы локализации и смысловые роли проверяются отдельно |
| Внешняя проверка заявлялась без чтения источника | Полные snapshots, SHA256, точные цитаты и проверка соответствия; reviewer access всегда `snapshot`, границы покрытия сохраняются |
| Защита чисел мешала доказательному исправлению исходной ошибки | После полного независимого review повторная диагностика использует копию исходника только с разрешёнными исправлениями; остальные изменения продолжают проверяться |
| Старые сохранённые receipts обходили текущий экспортный gate | v1/v2 доступны для чтения, но новый export требует текущего native run и независимых отзывов; старые v3 без новых доказательств также не проходят |
| Диагностический PASS воспринимался как готовность публикации | Диагностика явно сообщает `publication_ready=false` и необходимость независимого review |

Для доказательного исправления нужны точные уникальные непересекающиеся
фрагменты исходника, соответствующий фрагмент результата и цитата переданного
источника. Применение справа налево исключает каскадные замены. Отзыв остаётся
привязан к реальным исходным версиям, а не к служебной копии.

## Пути запуска

| Путь | Что проверено |
|---|---|
| Go `/v2/edit`: proofread, edit, rewrite, reconstruct, review/repair | Общий полный контракт, передача snapshots в writer/critic/repair, исходные ошибки и сохранение |
| Go legacy `/edit`: лёгкая, обычная, глубокая, переплавка | Полный независимый review, включая unchanged; повторная диагностика доказательных исправлений |
| AG-UI | Передача snapshots и общий legacy service, без отдельного облегчённого допуска |
| Общий API `/v1/editor/edit` | Передача snapshots в `/v2/edit`; список до восьми объектов, полная валидация на стороне EditorTeam |
| Python `/validate`, `validate-edit --review` | Полный receipt, оригинал, handoff/snapshots; диагностические ограничения сохраняются |
| `audit`, `/analyze`, прямые helpers | Содержательные сигналы и честная маркировка diagnostic-only; не публикационный допуск |
| Native publish submit/export | Отдельные независимые factual/literary reviews; вместе все 26 практик, логика, сохранение, исходные ошибки, хеши текста и источников; повторная проверка на export |
| Claude workflow, editor-team и manacost-publish skills | Согласованные инструкции, ссылки на общий каталог; механические запреты и квоты из старых инструкций устранены |

Все тематические практики из эссе сопоставлены с контекстными вопросами,
контрпримерами и действием в [матрице практик](EDITORIAL_PRACTICES.md).
Каталог не является детектором ИИ. Схема проверяет наличие и связь доказательств,
а содержательную правильность суждения всё равно оценивает reviewer.

## Метод повторного редакторского теста

Используются те же шесть полных извлечённых статей, всего 29 118 символов;
SHA256 каждого исходника сверяется с предыдущей выборкой. Подборка целевая,
не случайная; изображения, встроенные колоды и HTML-рендер вне её границ.
Writer и critic: Claude Sonnet 5.5, effort medium, отдельный контекст critic,
retrieval off. Проверка рассматривает исторический период публикаций.

Полные страницы четырёх первоисточников сохранены отдельно с URL, временем
получения и SHA256. Поздняя страница не доказывает содержание раннего анонса,
а частичное покрытие не считается подтверждением всех утверждений статьи.

Два предварительных экспериментальных прогона сохранены отдельно. В их
самописном адаптере обнаружена ошибка: `result.result` Claude CLI содержит
только последнее продолжение длинного ответа. Рабочий адаптер проекта уже
собирал полный stream. Поэтому итоговая когорта была запущена заново целиком
через его `Backend.argv` и `parse_claude_stream`, без выбора лучших попыток.
Отклонённые результаты возвращают исходник и не засчитываются как улучшение.

Полные пользовательские статьи, промпты и результаты остаются локально в
игнорируемой папке `build/editor-practices-fix-2026-10-23`; в Git они не включены.
Итоговая оценка отдельно различает факты, смысл/логику и авторский голос.

Независимый слепой модельный reviewer получил шесть полных A/B пар со случайным
расположением версий, без ключа и отчётов pipeline. Результат: **0 побед новой
версии, 0 побед исходника, 6 равных пар**. Две изменённые статьи получили только
косметические улучшения. Все 17 пар доказательных цитат проверены по исходному
пакету. Это один модельный reviewer, а не пользовательское исследование.

В прежних 25 контрольных утверждениях сохранены все 25; новых искажений нет,
исправлений прежних ошибок в выданном тексте — ноль. Внешняя проверка по той же
контрольной таблице: 14 подтверждены, 7 не покрыты или покрыты частично,
4 прежние проблемы остаются. Нельзя превращать 25 сохранённых утверждений
в 25 подтверждённых фактов или распространять вывод на все утверждения статей.

Практический результат: найдённые обходы полного контракта закрыты,
неполный или противоречивый отзыв не разрешает публикацию. При этом
**устойчивое содержательное улучшение статей этим прогоном не подтверждено**.
Два отказа из-за невалидных отзывов показывают ограничение надёжности модели;
остальные отказы не означают автоматического исправления исходных ошибок.
Система сохраняет материал и обозначает отказ, но ещё требует редакторского
разбора таких случаев. Случайно валидный receipt также не доказывает правильность
суждения модели: независимое чтение и проверка первоисточников остаются нужны.

Этот прогон проверяет работающий `/v2/edit` с настоящей моделью. Остальные пути
проверены кодом, контрактными и интеграционными тестами, пакетной проверкой;
шесть живых статей не запускались отдельно через каждый маршрут. В окончательном
прогоне добавлены snapshots, поэтому сравнение с v61 не является изолированным
A/B-тестом одной переменной. Предварительные прогоны с ошибкой транспортного
адаптера в итоговые оценки не включены.
