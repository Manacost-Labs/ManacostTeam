# План: рабочий Manacost Publish в Codex

Дата: 2026-10-10. База: выпуск Team skills 1.3.0, commit 84d4976.

## Результат для пользователя

В Codex можно вызвать `$manacost-publish`, указать тему или ссылку, формат и
нужны ли шорткоды. Codex читает MCP, сохраняет проверяемые источники, готовит
исследование и статью, получает независимые отзывы и возвращает полный текст
с локальным файлом. Незавершённый запуск можно продолжить по его папке.
Для этого пути не нужны отдельный LLM API, локальная LLM или запущенный Go gateway.

`ready` означает прохождение проверок рабочего материала. Публикация на сайте
и человеческое утверждение материала остаются отдельными действиями.

## Исходное состояние

- Go API уже имеет reconstruct, ResearchHandoff и отдельный fact review.
- Есть compiler chapter handoff, decision coverage и очередь вопросов.
- Из MCP сохранены 12 полных статей как private candidates.
- Есть заготовки blind review и optional extraction/evaluation adapters.
- Пока отсутствует единый возобновляемый процесс для native Codex-чата.
- Человеческий gold и измеренное сокращение времени редактора пока отсутствуют.

## Этапы и критерии приёмки

| № | Этап | Исполнитель | Проверяемый результат |
| --- | --- | --- | --- |
| 1 | Runner и журнал состояния | run_workflow | init/status/next/submit/revise/export; последовательные этапы, контроль хешей, продолжение без потери работы |
| 2 | Проверки фактов и целой статьи | review_gates | цитаты действия/условий/исключений/уверенности, патч и источники; независимый литературный отзыв; устаревший отзыв отклоняется |
| 3 | Корпус для человеческой оценки | benchmark_corpus | 12 карточек разметки, фиксированный train/holdout, реальное парное сравнение; candidate никогда не становится gold автоматически |
| 4 | Навык и простой вход | основной агент | установленный `$manacost-publish`, инструкции ролям, русский quickstart, автономный portable package |
| 5 | Интеграция и испытания | основной агент + независимый reviewer | проверки этапов/дрейфа/лимита исправлений/переносимости; старые Teams и API сохраняют поведение |
| 6 | Первый реальный запуск | native исследователь, автор и независимые reviewers | фактически прочитанные MCP-материалы, handoff, article.md, привязанные отзывы, final.md; явные ограничения даты/патча |
| 7 | Выпуск | основной агент | новые версии затронутых навыков, reproducible release, узкий commit и обычный push в origin |
| 8 | Калибровка после начала использования | редактор + Codex | фактические минуты/ошибки/предпочтения, сравнение только одинаковых case/patch, решения о дальнейших экспериментах |

Этапы 1–3 выполняются параллельно в разных файлах. Этап 4 может идти рядом
с ними; интеграция, проверки, реальный запуск и выпуск выполняются после
согласования контрактов. Сабагенты не коммитят и не публикуют данные.

## Контракт рабочего запуска

Владелец runner — EditorTeam; ResearchTeam передаёт существующий JSON handoff,
а не импортируется Python-зависимостью редактора. Runtime остаётся stdlib.

1. `sources`: полный текст, URL, время доступа, ID и хеш. Для MCP сохраняются
   все части до nextOffset=null; snippet не принимается как полный источник.
2. `research`: готовый ResearchHandoff из проверенных claims и источников,
   план глав, обязательные вопросы. Все цитаты должны находиться в собранных
   полных источниках. Критический пробел блокирует написание.
3. `draft`: связная статья на основании handoff и авторского стиля.
4. `fact_review`: независимый контекст candidate + handoff + evidence.
   Reviewer проверяет смысл и калибровку советов; программа проверяет форму
   доказательства, цитаты, принадлежность источников и хеши.
5. `literary_review`: независимая проверка пользы, композиции, русского языка,
   голоса и повторов между главами. Недостатки подтверждаются цитатой.
6. `ready`: экспорт полного материала после обеих пройденных проверок.

Изменение статьи или handoff инвалидирует предыдущие отзывы. На ошибку
проверки можно дать адресное исправление; максимум две ревизии. Все версии
и отклонённые отзывы сохраняются. Повреждённый запуск не объявляется готовым.
Ошибку самого reviewer report можно исправить одним recheck без изменения
статьи; прошлый отчёт сохраняется. Перенос внешнего экспортированного файла
показывается отдельным export_status и не блокирует продолжение внутреннего run.

## Роли и исследовательские пробелы

Для сложной темы начальные ветки независимы: официальные данные/статистика,
практика авторов и контрпримеры. Координатор объединяет их по evidence, а не
по числу голосов. Для небольшой редакторской задачи масштаб поиска уменьшается.

Gap Hunter получает brief, вопросы и утверждения без готового литературного
вывода. Важный пробел вызывает одну адресную волну поиска. Запрос и результат
записываются; запись в очереди не считается выполненным поиском. Для спорного
вывода максимум два раунда обсуждения, затем сохраняется неопределённость.

Новый навык описывает и использует native субагентов там, где это даёт
независимую проверку. Сам Python runner не запускает модели и не имитирует
их ответы. Нельзя называть создание задания выполненным исследованием.

## Корпус и сравнение

- Подготовить карточки 12 существующих статей, сохранить источник отдельно
  от edited reference и разметки.
- Split фиксировать до оптимизации; дубли одной статьи не делить между train
  и holdout. Изменение источника требует новой карточки/версии.
- Для gold нужны фактически заполненная разметка, reference, reviewer,
  reviewed_at и явное подтверждение человека. Codex может подготовить кандидатную
  разметку, но не выдаёт её за человеческое решение.
- В сравнении baseline/candidate использовать одинаковые источники, патч,
  постановку и бюджеты. Сохранять blind key отдельно от текста для оценки.
- Считать время и критические ошибки только по заполненным парным оценкам;
  отсутствие оценки оставлять null. Цель −30% — гипотеза, а не результат.

## Проверки и доставка

- Unit tests: порядок стадий, неподтверждённый handoff, исчезнувшее условие,
  усиление уверенности, новые числа/URL, устаревший патч, повреждение state,
  дрейф статьи/источника, повторные отзывы, превышенный repair budget.
- CLI smoke: путь с пробелами, русские данные, отказ от overwrite, resume и
  export; сообщения об ошибках должны быть понятны без traceback.
- Portable smoke: запуск новой команды из ZIP без checkout/optional libs;
  ссылки skill/reference валидны, все файлы и SHA256 воспроизводимы.
- Native forward test: другой агент выполняет реалистичный запрос по навыку
  без подсказки ожидаемого ответа. Последующие reviewers не видят self-review автора.
- Готовые изменения коммитятся/пушатся по постоянному указанию владельца.
  Проверяется совпадение remote SHA. Старые выпуски не меняются.

## Границы изменений и локальные данные

Основные новые файлы: `editor/src/editorteam/publication_{run,review,benchmark}.py`,
их tests, `teams/manacost-publish/`, public docs и release mappings.
Private runs, MCP-тексты, annotation и оценки остаются в ignored `build/`
либо в явно выбранной пользователем папке. В пакет входят только код,
инструкции и синтетические тестовые примеры.

Защищены прежние незавершённые пути: `editor/requirements-sage.txt`,
`.github/workflows/editor-cards.yml`, `.github/workflows/editor-evals.yml`.

## После первого рабочего запуска

По реальным ошибкам уточнять роли, вопросы и проверочные примеры. Затем
проверять полезность semantic retrieval, LangExtract, DSPy/RAGChecker и
расширенного Council на отдельном holdout. Добавлять observability или
графовую память только при выявленной потребности и измеримом результате.
