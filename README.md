# ManacostTeam

Единый монорепозиторий Manacost Labs для инструментов, skills и исследовательских контуров вокруг редакционного производства Hearthstone-контента. Репозиторий объединяет навигацию, историю и правила совместной работы, но не превращает независимые проекты в одно приложение.

## Состав

| Модуль | Что это | Когда использовать |
|---|---|---|
| [`editor/`](editor/) | Редакционный контур: проверка русскоязычных текстов Hearthstone, сохранение авторского голоса, контроль фактов и структуры. | Редактура гайдов, ревью материалов, работа с авторским корпусом. |
| [`research/`](research/) | Воспроизводимый deep-research: источники, снапшоты, проверка свежести, полноты и доказательств. | Исследование патчей, меты, лора и любых источникоёмких вопросов. |
| [`svg/`](svg/) | Генератор самодостаточных SVG-инфографик в стиле Hearthstone из JSON-спеков и живых данных. | Графики, тир-листы, дайджесты, карточки и изображения для статей/соцсетей. |
| [`job/`](job/) | Пакеты chat-skills для оценки вакансий и отбора игровых авторов. | Оценка вакансии, оффера или тестового задания прямо в чате. |

## Быстрый старт

```bash
git clone https://github.com/Manacost-Labs/ManacostTeam.git
cd ManacostTeam
```

После клонирования выберите модуль, а не устанавливайте зависимости всего репозитория разом. У каждого направления собственные команды, зависимости, правила и проверка качества.

## Локальные переменные окружения

В корне есть [`.env.example`](.env.example) и создан локальный `.env`. Последний исключён из Git и предназначен только для ваших ключей. По умолчанию `EDITOR_PROVIDER=none`: EditorTeam выполняет локальные проверки, не отправляя текст внешней модели.

Не заполняйте все строки подряд: задавайте только интеграции, которыми пользуетесь. Полный перечень и назначение переменных — в [`editor/.env.example`](editor/.env.example) и документации ResearchTeam. Учтите, что разные модули не подгружают корневой `.env` автоматически: перед запуском передайте его выбранной команде или продублируйте нужные переменные в окружение процесса.

### SVG-графики

```bash
# JSON-спек → SVG
python3 svg/hearthstone-svg-charts/scripts/make_chart.py spec.json -o chart.svg

# Проверка готового SVG
python3 svg/hearthstone-svg-charts/scripts/validate.py chart.svg
```

Подробные типы графиков, ассеты и работа с живыми данными — в [README модуля SVG](svg/README.md) и [AGENTS.md](svg/AGENTS.md).

### Исследования

```bash
# Базовая проверка skill-пакета
python3 research/deep-research/scripts/audit_skill.py

# Полный набор встроенных unit-тестов
python3 -m unittest discover -s research/deep-research/tests -p 'test_*.py' -v
```

Для настоящего исследования используйте процесс и шаблоны из [README модуля Research](research/README.md); результатом должен быть проверяемый research bundle, а не только текстовый ответ.

### Редакционный контур

`editor/` содержит CLI, навыки и правила, которые сохраняют голос автора и отделяют доказанный факт от стилистической правки. Начните с [README модуля Editor](editor/README.md), затем прочитайте [локальный AGENTS.md](editor/AGENTS.md): в нём есть обязательный контракт для агентов и серверной среды.

### JobTeam

В `job/skills/` лежат готовые `.skill`-пакеты. Они не требуют веб-приложения: после импорта в Codex вакансии, офферы и ответы авторов оцениваются прямо в чате. Назначение каждого пакета описано в [README JobTeam](job/README.md).

## Структура

```text
ManacostTeam/
├── editor/                  # редакционные skills, CLI, тесты и release-артефакты
├── research/                # research skill, evidence-протоколы и evaluation-наборы
├── svg/                     # SVG-генератор, игровые ассеты, примеры и превью
├── job/                     # chat-skills по найму и оценке вакансий
├── AGENTS.md                # общие правила работы для людей и AI-агентов
├── CONTEXT.md               # архитектурный контекст, границы и известные ограничения
├── CHANGELOG.md             # изменения на уровне монорепозитория
└── README.md                # карта репозитория и точки входа
```

Документация, конфигурация, тесты и зависимости модуля остаются внутри его каталога. Не переносите их на корень без отдельного решения: общая папка нужна лишь для действительно общих вещей.

## Работа с изменениями

1. Прочитайте корневой [AGENTS.md](AGENTS.md) и ближайшие инструкции конкретного модуля.
2. Ограничьте изменение одним модулем, если задача не требует явного межмодульного контракта.
3. Запустите проверку именно затронутого модуля.
4. Не редактируйте автоматически сгенерированные артефакты и игровые ассеты, если задача не требует их обновления.
5. В описании коммита и PR указывайте модуль: `editor:`, `research:`, `svg:` или `job:`.

## История миграции

12 сентября 2026 года исходные `EditorTeam`, `ResearchTeam` и `SVGTeam` импортированы через Git subtree в `editor/`, `research/` и `svg/`. Их исходная история доступна в графе коммитов. `JobTeam` добавлен как локальный набор skill-пакетов: отдельного Git-репозитория у него не было.

Подробные границы, договорённости и известные базовые ограничения — в [CONTEXT.md](CONTEXT.md). Изменения верхнего уровня — в [CHANGELOG.md](CHANGELOG.md).
