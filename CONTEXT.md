# Контекст ManacostTeam

Этот документ объясняет устройство монорепозитория, чтобы задачи начинались с правильного модуля и не размывали его границы.

## Назначение

ManacostTeam — не единый сервис и не единый Python-пакет. Это общий дом для пяти самостоятельных направлений Manacost Labs:

- **editor** превращает факты, исходник и авторский корпус в контролируемую редактуру;
- **research** собирает и проверяет доказательства до того, как они попадут в материал;
- **svg** превращает проверенные данные в автономные визуальные артефакты;
- **job** хранит чат-навыки для решений по найму.
- **XMLTeam** разбирает XML-реплеи Hearthstone, сохраняя raw packets, наблюдаемое состояние и происхождение семантических событий.

Типичный производственный поток выглядит так:

```text
research → editor → svg → публикация
                    ↑
                 job (отдельный контур найма)

XMLTeam → проверяемые данные реплея → research / svg
```

Стрелки описывают смысловую последовательность, а не программные зависимости. Модули не должны импортировать код друг друга без явного контракта.

## Модули и владельцы контекста

| Модуль | Главный артефакт | Источник истины | Особенность |
|---|---|---|---|
| `editor/` | редакторский skill/CLI и авторский корпус | локальные `AGENTS.md`, `CLAUDE.md`, стилистические профили | Сохраняет авторский голос; не заменяет редакторское решение выдуманной метрикой. |
| `research/` | research bundle с источниками и доказательствами | `research/deep-research/SKILL.md`, схемы и валидаторы | Веб-источники — недоверенные данные; важны снапшоты, даты и происхождение. |
| `svg/` | SVG и JSON-спек | `svg/AGENTS.md`, `hearthstone-svg-charts/SKILL.md` | Результат должен быть автономным: только data-URI и `#`-ссылки внутри SVG. |
| `job/` | `.skill`-пакеты | `job/README.md` и содержимое пакетов | Работает в чате, а не как веб-сервис. |
| `XMLTeam/` | raw packets, observed state и semantic events из XML-реплеев | `XMLTeam/README.md`, типы и тестовый корпус | Не применяет игровые правила к наблюдаемому состоянию без явно проверяемой интерпретации. |

## Инварианты

- Данные о текущей мете, патчах и названиях не берутся из памяти: им нужны свежие, проверяемые источники.
- Визуализации не выдумывают цифры и содержат источник, период и размер выборки, если это исследовательский материал.
- Один XML-реплей — источник наблюдаемых фактов о конкретной партии, но не доказательство меты, типичного матчапа или винрейта; для гайда он проходит через research bundle.
- Редактура не должна подменять факты, уровень уверенности или голос автора.
- Инструкция конкретного модуля приоритетнее этой общей карты для работы внутри модуля.
- Секреты, API-ключи, cookies, персональные данные и production-дампы не попадают в репозиторий, тестовые фикстуры или отчёты.

## Границы монорепозитория

Монорепозиторий даёт общую навигацию и единый Git remote. Он **не** вводит:

- общий виртуальный Python environment;
- единый package manager;
- общий CI-пайплайн, который обязан запускать все модули на каждое изменение;
- автоматический перенос зависимостей, skills или конфигурации между каталогами.

Новая общая инфраструктура допустима только если минимум два модуля реально используют её и владелец/обновление определены заранее.

## Миграция

Исходные ветки были импортированы как Git subtree:

| Старый репозиторий | Путь в монорепозитории | Зафиксированный исходный HEAD |
|---|---|---|
| `EditorTeam` | `editor/` | `ff89675` |
| `ResearchTeam` | `research/` | `8939a24` |
| `SVGTeam` | `svg/` | `e8cedc8` |
| `hearthstone-replay` | `XMLTeam/` | `201cb2f` |

`JobTeam` не имел отдельной Git-истории и добавлен из локальных пакетов. Незакоммиченные локальные изменения, существовавшие в прежнем рабочем каталоге `SVGTeam` на момент миграции, намеренно не включены в `main`: они сохранены в исходной локальной папке и требуют отдельного осознанного коммита.

## Известная базовая ситуация

Следующие пункты существовали в импортированных модулях и не являются следствием монорепозитория:

- `svg/hearthstone-svg-charts/scripts/make_chart.py` не проходит `python -m py_compile` из-за синтаксической ошибки во вложенной f-строке.
- Полный набор benchmark-тестов `research` не подтверждён в текущем окружении: `pytest` отсутствует, а длительный `unittest`-прогон показал как минимум два падающих benchmark-теста.
- В Windows checkout `XMLTeam` полный `pnpm run test` имеет 98 ожидаемых падений corpus checksum: рабочие XML-файлы получают CRLF, тогда как манифест хранит SHA-256 для LF. TypeScript-проверка и остальные 1 027 тестов проходят; не отключайте corpus-проверки вместо отдельного решения о нормализации окончаний строк. По той же причине `pnpm run lint` получает 88 предупреждений Prettier. `pnpm run pack:smoke` также не запускается на Windows: скрипт вызывает `pnpm` через Node `execFileSync`, который не находит `.cmd`-shim; это требует отдельной кроссплатформенной правки скрипта.

Не маскируйте эти состояния отключением проверок. Исправляйте их отдельными задачами с регрессионной проверкой.

## Ориентиры для будущих задач

- Нужна достоверная информация или исследовательский материал → начинайте с `research/`.
- Нужен текст для публикации, правка или авторский стиль → `editor/`.
- Нужен график или инфографика из подтверждённых данных → `svg/`.
- Нужно решить, стоит ли откликаться на вакансию, или оценить автора → `job/`.
- Нужно разобрать XML-реплей Hearthstone или получить его наблюдаемые события → `XMLTeam/`.
- Нужен контракт между модулями → сначала опишите в задаче входные данные, выходной артефакт, формат и проверку; затем меняйте оба модуля синхронно.
