# Требования владельца и архивные образцы в заданиях

База: 05649c5, чистая main, совпадающая с origin/main. Связанные изменения
выполняются в fix/persistent-editorial-context по manacost-ship и инженерному
профилю EditorTeam. Existing plans, корпус и материалы прежних запусков сохранены.
Serena/codegraph недоступны; Go, серверный адаптер и внешние API не меняются.

## Найденные причины

- `next --example-bank` передавал одобренные before/after-примеры только одному
  заданию draft. Это не чтение старых гайдов и не сохранённый выбор образцов.
- Native next не вызывал corpus_examples/style_examples. Общий локальный
  corpus содержал 49 constructed-guide; отдельные BG/архивные кандидаты не
  попадали в этот путь. Нельзя автоматически повысить их до approved/gold.
- `editorial-decisions.md` упоминался в инструкциях, но helper его не читал.
  Повторная передача замечаний полностью зависела от агента.
- В авторское задание включался полный каталог редакторских проверок.
- Локально установленный Codex manacost-publish был версией 1.9.0; 102 файла
  совпали с его манифестом. Обновления проекта не обновляли эту копию.

## Исправление и проверяемые границы

- Команда context фиксирует ограниченный пакет требований и точных архивных
  отрывков с источником, хешем, назначением и исключениями. Профиль совпадает
  с жанром запуска; корпус не меняется. Выбор текстов и извлечение требований
  выполняет агент по workflow, а не автоматический смысловой анализатор.
- Задание сохраняется между next/revise/continue-research. Новый пакет отменяет
  прежний допуск, но оставляет историю и экспорт. Одинаковый пакет ничего не
  сбрасывает. Старые runs читаются; следующий допуск требует контекст и reviews.
- Literary review охватывает каждый requirement/example id с цитатой и
  объяснением. Оба review связаны с хешем задания. Fact review не получает
  исторические образцы как evidence. Export повторяет проверки.
- Явно перечисленные запреты проверяются в тексте и подписях. Это не поиск
  синонимов/морфологии и не смысловая оценка. Необоснованное not_applicable
  и формально подходящую, но слабую прозу должен выявить reviewer.
- Автор получает конкретное задание впереди текста; каталог остаётся у
  проверяющих и доступен по ссылке. Meta-report использует тот же механизм.

## Свидетельства

- RED: новые сценарии падали до реализации; на ветке scoped suite прошёл
  70 тестов до добавления отдельного случая идемпотентной настройки.
- Полный Python editor на ветке: 1028 passed, 38 skipped, 5 subtests passed;
  корневой unittest: 257 tests, OK, 1 skipped. UTF-8 задан явно.
- Независимые read-only разборы проверили путь примеров и итоговую логику.
  Исправлены найденные пропуски HTML-заголовков, ложное совпадение в URL и
  старые ссылки на ручной editorial-decisions.md; добавлены проверки этих случаев.
- Smoke использовал реальные отрывки двух ранее выбранных BG-гайдов: нечётная
  стратегия и жуки. После нового процесса пакет и его хеш совпали. Статус
  candidate в corpus-bg сохранён. Материалы — ignored build/context-smoke-20261109.
- На одном и том же synthetic run размер авторского задания изменился с
  23960 до 9476 символов; новый пакет включал два реальных отрывка. Это мера
  доставки и объёма контекста, не доказательство улучшения качества прозы.
- Девять пакетов выпуска 1.20.13 собраны. Установленный manacost-publish
  обновлён до 1.12.11 из проверенного архива, 118 файлов сверены с манифестом.
  Прежняя папка целиком сохранена в локальном skill-backups; helper из новой
  установки выдал оба тех же отрывка. Уже загруженные клиентом инструкции
  могут потребовать нового чата для перечитывания навыка.

Платные API-прогоны, GitHub Release, deploy и Docker не запускались.
Широкая оценка качества новых статей и человеческое A/B не проводились;
результат подтверждает исправление передачи контекста и проверок исполнения.
