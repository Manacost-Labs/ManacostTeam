# Проверка отдельных правок

База: de1fb0a, Go v14 4e3cb7e. Gate A: GPT-6 Luna, read-only.
Параллельные изменения README, skills/funmeta и tests/test_funmeta.py чужие;
их не включать. Windows: server skillctl/ai-check и Serena/codegraph недоступны.
Применены EditorTeam, Go language/testing и monorepo gate.

Причины по сохранённым ответам: critic пропустил новый однокоренной повтор;
в другом тексте потребовал вернуть тему, уже явную из соседнего контекста.
Общие призывы проверять повторы уже присутствуют в v14.

Решение: обязательная структурированная оценка каждого лексического diff
в critic, с цитатой звучания, опорой области действия и отдельным решением.
Проверять покрытие, настоящие цитаты и согласованность с findings. Это не
детерминированное доказательство качества языка: его проверяет живой опыт.
Не вводить список запрещённых слов или автоматическую замену фраз корпуса.
Абзацы проверяются прежним отдельным контрактом; лимит repair и fact guards
не меняются. Цена — больше JSON в существующем вызове critic, без новой стадии.

      существующие тесты сохранения абзацев, сносок и смысла.
- [x] Gate B GPT-6 Luna, Go test/vet/build, review diff; код готов к commit.
- [ ] Свежие v14/v15 на неизменных десяти requests, все семь анализаторов.
- [ ] Два независимых слепых отзыва, история repair, полный текст в чате.
- [ ] Итоговый отчёт, commit и push только файлов этой задачи.

Gate B выявил раздувание контекста на больших входах. Исправлено: не более
16 областей, каждая выдержка не длиннее 300 символов; объединённые области
помечаются coarse. Полный текст остаётся основой проверки. Связанный finding
обязан дословно содержать проверенную цитату. Повторный Gate B: блокеров нет.
Проверены маршрут локального исправления с сохранением соседней правки и
абзаца, а также принятие сокращения при сохранённой теме из контекста и
обоснованном strength_changes. Это сценарные тесты, не оценки качества LLM.
Семантическую релевантность scope_quote оценивает модель; код проверяет её
наличие в тексте, а не истинность вывода. Отсутствующее пустое поле при нуле
лексических правок эквивалентно пустому массиву. Чужие правки funmeta были
закоммичены другой сессией как 46147f9; в эту задачу не включены.

v15 (614a59a): свежие 20 запросов завершены, 8/9 edited, 2/1 unchanged,
без rejected. Однако отдельный replay двух прежних черновиков показал:
critic v15 всё ещё принимает «играют не только игроки» и утверждает, что
эха нет. Этот опыт сохранён; общую задачу считать завершённой было рано.

v16: добавлена диагностика новых близких кириллических пар с общим началом.
Это эвристика звучания, не морфология: functional/unrelated допустимы без
repair. Для каждой показанной пары требуется quote/verdict/reason;
accidental требует адресного repair. Никаких словарей фраз десяти материалов
или автоматического переписывания. Пары source подавляются глобально;
существующие где-либо повторы могут быть пропущены. Регистр/ё нормализуются,
границы предложений/строк не пересекаются, максимум 4 подсказки на область
с явной меткой усечения. Перед приёмкой нужен replay и новый полный опыт.

v16 (d7856f7): контролируемый replay прошёл. Старая версия принимает эхо в
streams, новая возвращает нейтральную исходную фразу. В brawl новая сохраняет
сокращения, старая откатывает весь черновик. Это 9 живых вызовов и 8 явно
помеченных fixture-ответов анализа/черновика; в оценку десяти пар не входят.
Полный v16-прогон выявил независимый дефект retry: ошибка strength_changes
скрывала неправильную scope_quote, и единственная повторная проверка не
получала обе причины. v17 объединяет независимые ошибки валидаторов в том же
retry; все проверки и лимиты остаются. Новый RED-тест воспроизводит дефект.
